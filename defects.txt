Defects discovered while verifying README examples
===============================================

Summary (high level)
- README has many mismatches vs actual implementation (route names, API presence, field requirements, DB path, session / env var docs).

List of defects and reproduction steps
-------------------------------------

1) Wrong route names documented
   - README claims endpoints: /signup, /signin, /profile
   - Actual code implements: /register, /login, /dashboard (and /logout)
   - Reproduction: try to visit /signup -> 404
     Example: curl -i http://localhost:5000/signup  -> 404 Not Found

2) API endpoints (/api/register, /api/login) do not exist
   - README documents JSON API, but routes are not present and return 404
   - Reproduction: curl -i -X POST http://localhost:5000/api/register -d '{"user":"x","pass":"y","mail":"x@x"}' -H 'Content-Type: application/json'
     -> 404 Not Found

3) Register fields mismatch: README lists confirm_password and email optional
   - Implementation does not have confirm_password and email is required
   - Reproduction: POST /register with empty email results in validation error

4) Password minimum length mismatch
   - README states minimum length 3. Code's `RegisterForm` has Length(min=6).
   - Reproduction: POST /register with password shorter than 6 fails validation.

5) Database path mismatch
   - README says database file is data/database.sqlite3
   - app.py sets app.config['DATABASE'] = 'app.db'

6) Session/Redis and env var mismatch
   - README claims sessions are stored in Redis and FLASK_SECRET env var controls CSRF.
   - No Redis usage is present; code uses app.config['SECRET_KEY'] and Flask-WTF CSRF via secret key.

7) Missing run_tests.sh in original README
   - README instructs to run bash run_tests.sh but file was not present.

Notes and Recommendations
------------------------

- If API endpoints are desired, implement /api/register and /api/login handlers with JSON contracts, or remove them from docs.
- Decide whether to use server-side sessions (Redis) — if so add configuration and documentation, otherwise remove Redis references.
- If environment variable names are preferred (e.g., FLASK_SECRET), change the code to read from environment or document the correct config key.
